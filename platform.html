E-1
Problem

The same corrections, every cycle

PV, battery storage and emergency power submittals fail plan check for a short list of recurring reasons: a backfed breaker that breaks the 120% busbar rule, a roof array with no rapid shutdown method, a generator system with no selective coordination study, a single-line diagram that leaves out the battery disconnect.

Each miss costs a full correction cycle for the applicant and a second review for the jurisdiction. Most of these checks are arithmetic or a yes/no on whether a required item is in the package. They can run before anyone opens the plans.

Ohmsight turns those checks into a rule engine, scores every finding on severity and likelihood, and records the reviewer's decision so the program can see which deficiencies keep coming back.

Applicants and designers

Pre-check before submitting

Enter key project data or upload it, see the likely corrections ranked by risk, and fix them before the first submittal.

Plan reviewers

Review riskiest items first

A checklist ordered by risk score with the calculation shown, one-click dispositions, and a correction list ready to paste.

Program managers

See deficiency trends

Track which rules fail most, by system type and month, to target bulletins, training and checklist updates.

E-2
Method

From project data to a ranked checklist

  1. IntakeKey values from the submittal: module and inverter ratings, busbar and breaker sizes, ESS capacity and location, generator rating and calculated load, and which required documents are in the package. Entered in a form or uploaded as JSON or CSV.
  2. Rule engineEach rule is a small, testable function tied to one code section. Rules either calculate (string voltage at design low temperature, 120% busbar sum) or confirm that a required item is present.
  3. Risk rankingEvery finding gets a severity and a likelihood score. The product ranks the list so life-safety calculations lead and labeling items trail.
  4. Reviewer dispositionThe reviewer confirms, clears or marks each item not applicable. Confirmed items become a numbered correction list.
  5. Trend analyticsDispositions roll up into a dashboard of deficiency rates by rule, system type and month.
Risk score
Risk = Severity (1-5) × Likelihood (1-5)
S5Fire or life-safety exposure, or loss of emergency power
S4Code violation that blocks approval or damages equipment
S3Design information missing; reviewer cannot verify
S2Labeling, directory or documentation gap
L5Calculated from submitted values
L4Required item absent from the package
L3Within 3% or 10% of a limit; verify
▲ Critical 20-25 ◆ High 12-19 ● Medium 6-11 ○ Low 1-5

      Project Ohmsight
      
A pre-check and review-assist tool for PV, energy storage and emergency power submittals, led by electrical engineer Ezeoma Igwe.

      
Ohmsight flags likely deficiencies. It does not approve plans. Final code determinations rest with the authority having jurisdiction.
